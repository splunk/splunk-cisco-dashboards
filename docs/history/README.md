# Documentation history

This directory records how to handle historical implementation notes. It is not
the current source of product behavior or release status.

- `SESSION_LOG.md` explains why deployment-specific session notes are not kept
  in the working tree.
- `../RELEASE_NOTES.md` is the current release-level change record.
- Git history is the authoritative record of file changes.

Use Git history for implementation forensics. Do not add customer names,
locations, topology details, event dates, or environment-specific identifiers
to tracked documentation.
